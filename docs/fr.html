Dador de objetos

Un système permettant de proposer des produits via un menu, soit rezzé dans le monde, soit attaché à un avatar.

CommencerRéférence rapide
Menus configurablesRezzé ou attachéObjets et notecardsObjets temporaires compatibles

Ce qu’il peut faire

  • Livrer des produits dans l’inventaire
  • Afficher des objets temporaires attachés
  • Combiner temporaire + copie permanente
  • Fonctionner avec plusieurs utilisateurs
  • Utiliser des animations configurables
  • Afficher des messages de livraison

Aucun résultat

Essayez un autre terme de recherche.

01

Premiers pas

Vérifiez le contenu et préparez le Dador à l’utilisation.

Contenu du Dador

Ces quatre scripts doivent rester dans le Dador :

Dador_Main v1.4.1
Dador_Config_Productos v1.3.4
Dador_Anim_portador v1.3.1
Dador_Menu_Multiusuario v1.0.1

Vous trouverez également Config Dador, Lista Autorizados, les animations utilisées, les produits installés et d’éventuels composants TEMP_.

Les noms exacts sont obligatoires

La notecard principale doit s’appeler exactement Config Dador. Si vous utilisez ACCESO=LISTA, la notecard doit s’appeler exactement Lista Autorizados. Ne renommez pas les scripts ni les composants TEMP_.

Premier démarrage

  1. Rezzez une copie du Dador dans une zone où vous pouvez modifier les objets et exécuter les scripts.
  2. Cliquez avec le bouton droit sur le Dador et choisissez Modifier.
  3. Ouvrez l’onglet Contenu.
  4. Vérifiez la présence des quatre scripts principaux.
  5. Vérifiez que Config Dador est présent.
  6. Vérifiez que les animations indiquées dans Config Dador se trouvent réellement dans le Dador.
  7. Ouvrez Config Dador, ne modifiez que les options documentées et enregistrez.
  8. Attendez quelques secondes avant de tester.

Le système recharge automatiquement sa configuration lorsque l’inventaire change, notamment après l’enregistrement de Config Dador ou l’ajout/la suppression d’animations, de produits ou de composants TEMP_.

02

Config Dador

Le centre de contrôle du produit, sans modifier les scripts.

Les lignes de configuration utilisent le format NOMBRE=VALOR. Les noms de paramètres affichés dans les blocs de code ne doivent pas être traduits.

NOMBRE=VALOR

Règles

  • Utilisez un point pour les décimales : 1.2.
  • N’utilisez pas de virgule comme séparateur décimal : 1,2.
  • Les lignes commençant par # sont des commentaires.
  • Les lignes vides sont autorisées.
  • Config Dador accepte jusqu’à 100 lignes physiques.
Exemple minimal
ACCESO=TODOS
MENUS_SIMULTANEOS=NO

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

Exemple complet

ACCESO=TODOS

MENUS_SIMULTANEOS=NO

FRASE_DAR=
MENSAJE_AUTOMATICO=SI
DISTANCIA_MENSAJES=20

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

ANIM_PORTAR=Anim_Portar
ANIM_SERVIR=Anim_Servir
ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado

DURACION_ANIM_SERVIR=5.0
DURACION_ANIM_RECIBIR_ANEXADO=5.0
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

RETARDO_APARICION_TEMP_ANEXADO=0
RETARDO_APARICION_TEMP_NO_ANEXADO=0
03

Qui peut l’utiliser

Quatre modes d’accès.

TODOS

ACCESO=TODOS

N’importe quel avatar peut utiliser le Dador.

PROPIETARIO

ACCESO=PROPIETARIO

Seul le propriétaire peut l’utiliser.

GRUPO

ACCESO=GRUPO

Seuls les avatars ayant le même groupe actif que le Dador peuvent l’utiliser.

LISTA

ACCESO=LISTA

Seuls les avatars inclus dans Lista Autorizados peuvent l’utiliser.

Lista Autorizados

Écrivez un Username Second Life par ligne. N’utilisez pas les Display Names.

avatar.ejemplo
OtroUsuario

Les lignes vides et les commentaires commençant par # sont autorisés. Maximum : 20 avatars. Si un Username ne peut pas être résolu, le mode LISTA reste bloqué jusqu’à correction.

04

Menu individuel ou simultané

Choisissez le comportement du Dador lorsque plusieurs personnes l’utilisent.

Classique

MENUS_SIMULTANEOS=NO

Une seule personne peut utiliser le Dador à la fois. Pendant qu’elle navigue, sélectionne et reçoit, une autre personne verra que le Dador est occupé.

Lorsque le Dador est attaché, ANIM_SERVIR fonctionne normalement dans ce mode.

Multiutilisateur

MENUS_SIMULTANEOS=SI

Plusieurs avatars peuvent ouvrir et parcourir leur propre menu en même temps. Les livraisons sont ensuite traitées une par une et dans l’ordre.

Limites : jusqu’à 20 menus simultanés et 20 demandes de livraison en attente.

Animations en mode simultané

Lorsque le Dador est attaché, ANIM_SERVIR n’est pas jouée. ANIM_PORTAR, les animations du destinataire, les temporaires et les copies permanentes continuent de fonctionner.

Menu des produits

  • Affiche jusqu’à 3 produits par page.
  • Utilise Anterior et Siguiente lorsqu’il y a plusieurs pages.
  • Inclut Cancelar.
  • Chaque menu expire après environ 30 secondes d’inactivité.
05

Distances

Trois valeurs distinctes contrôlent l’ouverture du menu et la finalisation d’une livraison.

RADIO_USO

0.5 .. 300.0 m

Distance maximale depuis laquelle un avatar peut commencer à utiliser le Dador et ouvrir le menu.

DISTANCIA_ANEXADO

0.1 .. 100.0 m

Distance finale lorsque le Dador est attaché. Elle est mesurée horizontalement entre le destinataire et l’avatar porteur.

DISTANCIA_NO_ANEXADO

0.1 .. 100.0 m

Distance finale lorsque le Dador est rezzé. Elle est mesurée depuis le bord de l’objet.

Règle obligatoire

DISTANCIA_ANEXADO et DISTANCIA_NO_ANEXADO ne doivent jamais être supérieures à RADIO_USO.

Valide

RADIO_USO=20.0
DISTANCIA_ANEXADO=15.0
DISTANCIA_NO_ANEXADO=10.0

Invalide

RADIO_USO=10.0
DISTANCIA_ANEXADO=15.0
06

Animations

Quatre animations indépendantes et facultatives, configurées avec leur nom exact dans l’inventaire.

Chaque animation peut être désactivée

Laissez la valeur d’une animation vide pour qu’elle ne soit pas jouée. Les animations actives et désactivées peuvent être combinées librement.

ANIM_PORTAR=
ANIM_SERVIR=
ANIM_RECIBIR_ANEXADO=
ANIM_RECOGER_NO_ANEXADO=

ANIM_PORTAR

Pose permanente de l’avatar qui porte le Dador attaché. Si elle est utilisée, elle doit être préparée en loop. Vide signifie qu’aucune pose de portage n’est jouée.

ANIM_PORTAR=Anim_Portar

ANIM_SERVIR

Animation temporaire du porteur lorsqu’il sert. Elle est utilisée uniquement avec le Dador attaché et MENUS_SIMULTANEOS=NO. Vide signifie que le porteur ne joue aucune animation de service.

ANIM_SERVIR=Anim_Servir
DURACION_ANIM_SERVIR=5.0

ANIM_RECIBIR_ANEXADO

Animation du destinataire lorsque le Dador est attaché. Elle peut rester vide.

ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
DURACION_ANIM_RECIBIR_ANEXADO=5.0

ANIM_RECOGER_NO_ANEXADO

Animation du destinataire lorsque le Dador est rezzé. Elle peut rester vide.

ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

Les trois durées d’animation temporaires acceptent toujours 0.1 .. 60.0 secondes. Si l’animation correspondante est vide, sa durée est simplement ignorée. ANIM_PORTAR n’a pas de durée.

Utiliser des animations achetées

Il n’est pas nécessaire de les renommer. Si une ligne ANIM_* contient un nom, placez cette animation dans le Dador et indiquez son nom exact dans l’inventaire. Si la ligne est vide, aucune animation n’est requise pour ce rôle.

ANIM_RECIBIR_ANEXADO=[Tienda] Take Drink Bento 03

Quand un objet temporaire apparaît

RETARDO_APARICION_TEMP_ANEXADO=1.3
RETARDO_APARICION_TEMP_NO_ANEXADO=1.6

Avec une animation de réception active, le délai doit rester dans la durée de cette animation. Si l’animation de réception correspondante est vide, il n’y a aucune animation avec laquelle se synchroniser : l’objet temporaire apparaît immédiatement et ce délai n’intervient pas.

07

Messages de livraison

Utilisez une phrase personnalisée, le message automatique ou les deux.

FRASE_DAR

Définit une phrase personnalisée. Le nom du paramètre doit rester FRASE_DAR.

FRASE_DAR=Que aproveche!

Laissez vide si vous ne voulez pas de phrase personnalisée :

FRASE_DAR=

MENSAJE_AUTOMATICO

Utilisez SI pour activer le message automatique et NO pour le désactiver. Ne traduisez pas SI/NO dans Config Dador.

MENSAJE_AUTOMATICO=SI

Avec SI, le Dador ajoute ce format :

<Nombre del Dador> te ha dado <Nombre del producto>.
FRASE_DARAutomatiqueRésultat
VideNOAucun message
VideSIAutomatique uniquement
Avec texteNOPersonnalisé uniquement
Avec texteSIPersonnalisé + automatique

DISTANCIA_MENSAJES

10Chuchotement · ~10 m
20Chat normal · ~20 m
100Cri · ~100 m
Pourquoi le nom du Dador peut apparaître deux fois

Second Life affiche automatiquement le nom de l’objet qui parle. Le message automatique peut également contenir ce même nom.

08

Créer et ajouter des produits

Comment préparer de zéro un objet ou une notecard compatible avec le Dador.

Ce qu’il vous faut

Pour une copie normale, il suffit de préparer le produit et sa description. Si le produit utilise une partie temporaire, utilisez le Script_Temporal fourni avec le système et, lorsque nécessaire, une notecard nommée exactement Config Temporal. Le manuel explique la configuration ; il n’est pas nécessaire de modifier le code du script.

1. Décider ce que le produit doit remettre

Le Dador lit la description de l’élément principal et utilise deux indicateurs : T pour la partie temporaire et C pour la copie permanente.

DescriptionRésultatUtilisation typique
T=NO;C=SICopie permanente uniquementObjet ou notecard remis dans l’inventaire
T=SI;C=NOTemporaire uniquementProp attaché temporairement sans laisser de copie
T=SI;C=SITemporaire + copie permanenteScène temporaire plus copie dans l’inventaire

Une description vide équivaut à T=NO;C=SI. N’utilisez pas T=NO;C=NO : le Dador le considère comme invalide car il n’y aurait rien à remettre.

2. Choisir la structure du produit

Objet avec copie

Bière
Description: T=NO;C=SI

Ne nécessite pas Script_Temporal.

Objet temporaire

Bière
Description: T=SI;C=NO

Si TEMP_Bière n’existe pas, l’objet principal peut lui-même servir d’objet temporaire.

Objet + TEMP_

Bière
TEMP_Bière

Si TEMP_Bière existe, le Dador le préfère comme composant temporaire. Le produit visible dans le menu reste Bière.

Notecard + TEMP_

Recette de bière
TEMP_Recette de bière

Pour une notecard avec T=SI, l’objet TEMP_<nom exact> est obligatoire.

3. Préparer l’objet temporaire

L’objet qui fonctionnera comme composant temporaire doit contenir le noyau temporaire et, si nécessaire, sa configuration et ses animations :

Script_Temporal
Config Temporal
Animations propres (facultatives)
Noms exacts

La notecard doit s’appeler exactement Config Temporal. Le préfixe TEMP_ doit également être conservé exactement et suivi du nom complet du produit principal.

La politique T/C doit être placée dans la description du produit principal. Si vous utilisez un objet auxiliaire TEMP_, il n’est pas nécessaire de répéter cette politique dans sa description : le Dador utilise celle du produit principal.

4. Configurer Config Temporal

Les paramètres généraux doivent apparaître avant de commencer la séquence ANIMACIONn/TIEMPOn.

Si l’objet temporaire ne possède pas d’animations propres, utilise le comportement final par défaut DESANEXAR_AL_FINAL=SI et n’a pas besoin de phrase propre, Config Temporal peut être omise. Pour rester attaché avec DESANEXAR_AL_FINAL=NO, émettre FRASE_COGER ou contrôler une séquence, Config Temporal est nécessaire.

Config Temporal accepte jusqu’à 100 lignes physiques. Utilisez un point décimal pour les durées, par exemple 4.2.

Sans animations propres

FRASE_COGER=
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=SI

ANIMACION1=
TIEMPO1=

Avec une animation

FRASE_COGER=Vous avez pris une bière.
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=NO

ANIMACION1=BRAZO COGER
TIEMPO1=4.2

FRASE_COGER

Texte prononcé par l’objet temporaire environ une seconde après l’attach. Peut rester vide pour ne rien dire.

DISTANCIA_MENSAJE

Accepte uniquement 10, 20 ou 100. Si omis, la valeur par défaut est 20.

DESANEXAR_AL_FINAL

SI masque et détache l’objet temporaire à la fin. NO le laisse visible et attaché jusqu’à ce que l’avatar le retire.

ANIMACIONn / TIEMPOn

Jusqu’à 10 animations, numérotées consécutivement à partir de 1. Chaque durée réelle doit être comprise entre 0.1 et 60.0 secondes.

Ne confondez pas les deux distances de messages

DISTANCIA_MENSAJE appartient à Config Temporal. DISTANCIA_MENSAJES, avec un S final, appartient à Config Dador. Ce sont deux paramètres différents.

5. Règles des animations temporaires

  • Les paires doivent être consécutives : ANIMACION1 + TIEMPO1, puis ANIMACION2 + TIEMPO2, etc.
  • N’insérez pas FRASE_COGER, DISTANCIA_MENSAJE ou DESANEXAR_AL_FINAL entre une animation et son temps.
  • Le nom doit correspondre exactement à une animation présente dans l’objet temporaire.
  • Une paire vide telle que ANIMACION1= + TIEMPO1= ferme explicitement la séquence et permet de ne jouer aucune animation même si des animations inutilisées restent dans l’inventaire.
  • Ne déclarez pas de nouvelles animations après une paire vide.

6. Vérifier les permissions

Le Dador vérifie les permissions nécessaires pour remettre des copies et créer des temporaires. Les éléments utilisés comme temporaires doivent autoriser Copy + Transfer, y compris le contenu qui doit les accompagner. Si vous modifiez les permissions après la préparation, répétez le test complet.

7. Tester le produit avant de le placer dans le Dador

Avec Script_Temporal v2.6.4, rezzez manuellement l’objet temporaire. Comme il ne reçoit pas les données de démarrage du Dador, il passe en mode préparation : il ne s’attache pas, ne demande pas de permissions, ne lance pas d’animations et ne se supprime pas.

Le diagnostic vérifie la description T/C, Config Temporal, ses paramètres, les animations et l’état général du produit. Quand tout est correct, vous devez obtenir quelque chose comme :

OK: T=SI;C=SI (temporal + copia).
PREP v2.6.4 | objeto='Pepo' | anim=1 | secuencia=1
RESULTADO: LISTO para introducir en el Dador.
MEM: usada=... libre=...

Si RESULTADO: NO LISTO apparaît, corrigez d’abord les erreurs indiquées. Le diagnostic se relance lorsque l’inventaire change et surveille également le nom et la description pendant la préparation.

8. Placer le produit dans le Dador

  1. Lorsque le diagnostic indique LISTO, reprenez l’objet s’il était rezzé.
  2. Modifiez le Dador et ouvrez Contenu.
  3. Ajoutez le produit principal.
  4. S’il utilise un composant séparé TEMP_, ajoutez-le également.
  5. Conservez sans modification les noms, la description, les scripts, notecards, animations et permissions déjà testés.
  6. Attendez quelques secondes pendant le rechargement du catalogue.
  7. Touchez le Dador et vérifiez que le produit principal apparaît dans le menu.
  8. Effectuez une livraison réelle et vérifiez la partie temporaire ainsi que la copie permanente, selon le cas.
30produits maximum
128éléments d’inventaire maximum
Résumé rapide

Choisissez d’abord T/C. Préparez ensuite la partie temporaire si elle existe, configurez Config Temporal, rezzez l’objet et attendez RESULTADO: LISTO. Placez seulement ensuite le produit et son éventuel composant TEMP_ dans le Dador et testez une livraison complète.

09

Objets temporaires et TEMP_

Produits visuels pouvant apparaître attachés pendant une livraison.

Certains produits préparés incluent un objet associé dont le nom commence exactement par TEMP_.

Nota de demostración
TEMP_Nota de demostración

Le produit principal apparaît dans le menu. L’élément TEMP_ est interne et n’apparaît pas comme produit séparé.

Ce qu’un temporaire peut faire

  • Disparaître automatiquement après ses animations.
  • Exécuter une ou plusieurs animations propres.
  • Rester attaché après la fin de la séquence.
  • Rester attaché jusqu’à ce que l’avatar le retire manuellement.

Démo de bière

Ajoutez la bière préparée au Dador, ne changez ni son nom ni sa description, attendez le rechargement et sélectionnez-la dans le menu.

Notecard + TEMP_

Ajoutez la notecard et son objet TEMP_ associé sans changer leurs noms. La notecard doit apparaître dans le menu, pas le composant TEMP_.

10

Utilisation rezzée et attachée

Deux façons d’utiliser le même système.

Rezzé
  1. Placez le Dador dans le monde.
  2. L’utilisateur doit se trouver dans RADIO_USO.
  3. Touchez le Dador et sélectionnez un produit.
  4. Pour terminer la livraison, restez dans DISTANCIA_NO_ANEXADO.
  5. Le destinataire utilise ANIM_RECOGER_NO_ANEXADO.

ANIM_PORTAR et ANIM_SERVIR n’interviennent pas en mode rezzé.

Attaché
  1. Attachez le Dador à l’avatar qui servira les produits.
  2. ANIM_PORTAR démarre automatiquement.
  3. Un autre avatar touche le Dador et choisit un produit.
  4. Le destinataire doit se trouver dans DISTANCIA_ANEXADO.
  5. Le destinataire utilise ANIM_RECIBIR_ANEXADO.

Avec MENUS_SIMULTANEOS=NO, le porteur joue également ANIM_SERVIR.

Le porteur ne peut pas se servir lui-même

L’avatar qui porte le Dador ne peut pas utiliser son propre Dador pendant qu’il le porte. Il est destiné à servir d’autres avatars.

11

Dépannage

Vérifications qui résolvent la plupart des problèmes courants.

Le menu n’apparaît pas

Vérifiez RADIO_USO, le mode ACCESO, que le Dador a fini de charger, que des produits valides existent et que Config Dador ne contient pas d’erreurs.

J’obtiens « Pas d’accès »

Pour GRUPO, vérifiez le groupe du Dador et le groupe actif de l’avatar. Pour LISTA, utilisez des Usernames valides, pas des Display Names.

Le Dador indique qu’il est occupé

Avec MENUS_SIMULTANEOS=NO, c’est normal : une seule personne peut l’utiliser à la fois.

Trop de menus ou de demandes

Le mode simultané accepte jusqu’à 20 sessions de menu actives et 20 sélections en attente.

Le Dador me demande de me rapprocher

Vous pouvez être dans RADIO_USO tout en étant hors de la distance finale. Vérifiez DISTANCIA_ANEXADO ou DISTANCIA_NO_ANEXADO.

Une animation ne fonctionne pas

Vérifiez qu’elle se trouve dans le Dador, que son nom correspond exactement et que la durée est correcte. ANIM_PORTAR doit aussi être préparée pour loop.

ANIM_SERVIR ne fonctionne pas

Si MENUS_SIMULTANEOS=SI, c’est volontaire.

Un temporaire apparaît trop tôt ou trop tard

Ajustez RETARDO_APARICION_TEMP_ANEXADO ou RETARDO_APARICION_TEMP_NO_ANEXADO.

Un temporaire ne disparaît pas

Cela peut être correct. Certains produits sont conçus pour rester attachés jusqu’à ce que le destinataire les retire.

Aucun message de livraison n’apparaît

Avec FRASE_DAR= et MENSAJE_AUTOMATICO=NO, l’absence de message est le résultat attendu.

DISTANCIA_MENSAJES provoque une erreur

Seules les valeurs 10, 20 ou 100 sont acceptées.
