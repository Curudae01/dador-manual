Delivery

Un système permettant de proposer des produits via un menu, soit rezzé dans le monde, soit attaché à un avatar.

CommencerRéférence rapide
Menus configurablesRezzé ou attachéObjets et notecardsObjets temporaires compatibles

Ce qu’il peut faire

  • Livrer des produits dans l’inventaire
  • Afficher des objets temporaires attachés
  • Combiner temporaire + copie permanente
  • Fonctionner avec plusieurs utilisateurs
  • Utiliser des animations configurables
  • Afficher des messages de livraison

Aucun résultat

Essayez un autre terme de recherche.

01

Premiers pas

Vérifiez le contenu et préparez le Dador à l’utilisation.

Contenu du Dador

Ces quatre scripts doivent rester dans le Dador :

Dador_Main v1.4.1
Dador_Config_Products v1.3.4
Dador_Carrier_Animation v1.3.1
Dador_Multiuser_Menu v1.0.1

Vous trouverez également Dador Config, Authorized Users, les animations utilisées, les produits installés et d’éventuels composants TEMP_.

Les noms exacts sont obligatoires

La notecard principale doit s’appeler exactement Dador Config. Si vous utilisez ACCESS=LIST, la notecard doit s’appeler exactement Authorized Users. Ne renommez pas les scripts ni les composants TEMP_.

Premier démarrage

  1. Rezzez une copie du Dador dans une zone où vous pouvez modifier les objets et exécuter les scripts.
  2. Cliquez avec le bouton droit sur le Dador et choisissez Modifier.
  3. Ouvrez l’onglet Contenu.
  4. Vérifiez la présence des quatre scripts principaux.
  5. Vérifiez que Dador Config est présent.
  6. Vérifiez que les animations indiquées dans Dador Config se trouvent réellement dans le Dador.
  7. Ouvrez Dador Config, ne modifiez que les options documentées et enregistrez.
  8. Attendez quelques secondes avant de tester.

Le système recharge automatiquement sa configuration lorsque l’inventaire change, notamment après l’enregistrement de Dador Config ou l’ajout/la suppression d’animations, de produits ou de composants TEMP_.

02

Dador Config

Le centre de contrôle du produit, sans modifier les scripts.

Les lignes de configuration utilisent le format NOMBRE=VALOR. Les noms de paramètres affichés dans les blocs de code ne doivent pas être traduits.

NOMBRE=VALOR

Règles

  • Utilisez un point pour les décimales : 1.2.
  • N’utilisez pas de virgule comme séparateur décimal : 1,2.
  • Les lignes commençant par # sont des commentaires.
  • Les lignes vides sont autorisées.
  • Dador Config accepte jusqu’à 100 lignes physiques.
Exemple minimal
ACCESS=ALL
SIMULTANEOUS_MENUS=NO

USE_RADIUS=5.0
ATTACHED_DISTANCE=2.0
REZZED_DISTANCE=1.2

Exemple complet

ACCESS=ALL

SIMULTANEOUS_MENUS=NO

DELIVERY_MESSAGE=
AUTOMATIC_MESSAGE=YES
MESSAGE_DISTANCE=20

USE_RADIUS=5.0
ATTACHED_DISTANCE=2.0
REZZED_DISTANCE=1.2

CARRY_ANIMATION=Anim_Carry
SERVE_ANIMATION=Anim_Serve
ATTACHED_RECEIVE_ANIMATION=Anim_Receive_Attached
REZZED_PICKUP_ANIMATION=Anim_Pickup_Rezzed

SERVE_ANIMATION_DURATION=5.0
ATTACHED_RECEIVE_ANIMATION_DURATION=5.0
REZZED_PICKUP_ANIMATION_DURATION=5.0

ATTACHED_TEMP_SHOW_DELAY=0
REZZED_TEMP_SHOW_DELAY=0
03

Qui peut l’utiliser

Quatre modes d’accès.

ALL

ACCESS=ALL

N’importe quel avatar peut utiliser le Dador.

OWNER

ACCESS=OWNER

Seul le propriétaire peut l’utiliser.

GROUP

ACCESS=GROUP

Seuls les avatars ayant le même groupe actif que le Dador peuvent l’utiliser.

LIST

ACCESS=LIST

Seuls les avatars inclus dans Authorized Users peuvent l’utiliser.

Authorized Users

Écrivez un Username Second Life par ligne. N’utilisez pas les Display Names.

avatar.ejemplo
OtroUsuario

Les lignes vides et les commentaires commençant par # sont autorisés. Maximum : 20 avatars. Si un Username ne peut pas être résolu, le mode LIST reste bloqué jusqu’à correction.

04

Menu individuel ou simultané

Choisissez le comportement du Dador lorsque plusieurs personnes l’utilisent.

Classique

SIMULTANEOUS_MENUS=NO

Une seule personne peut utiliser le Dador à la fois. Pendant qu’elle navigue, sélectionne et reçoit, une autre personne verra que le Dador est occupé.

Lorsque le Dador est attaché, SERVE_ANIMATION fonctionne normalement dans ce mode.

Multiutilisateur

SIMULTANEOUS_MENUS=YES

Plusieurs avatars peuvent ouvrir et parcourir leur propre menu en même temps. Les livraisons sont ensuite traitées une par une et dans l’ordre.

Limites : jusqu’à 20 menus simultanés et 20 demandes de livraison en attente.

Animations en mode simultané

Lorsque le Dador est attaché, SERVE_ANIMATION n’est pas jouée. CARRY_ANIMATION, les animations du destinataire, les temporaires et les copies permanentes continuent de fonctionner.

Menu des produits

  • Affiche jusqu’à 3 produits par page.
  • Utilise Previous et Next lorsqu’il y a plusieurs pages.
  • Inclut Cancel.
  • Chaque menu expire après environ 30 secondes d’inactivité.
05

Distances

Trois valeurs distinctes contrôlent l’ouverture du menu et la finalisation d’une livraison.

USE_RADIUS

0.5 .. 300.0 m

Distance maximale depuis laquelle un avatar peut commencer à utiliser le Dador et ouvrir le menu.

ATTACHED_DISTANCE

0.1 .. 100.0 m

Distance finale lorsque le Dador est attaché. Elle est mesurée horizontalement entre le destinataire et l’avatar porteur.

REZZED_DISTANCE

0.1 .. 100.0 m

Distance finale lorsque le Dador est rezzé. Elle est mesurée depuis le bord de l’objet.

Règle obligatoire

ATTACHED_DISTANCE et REZZED_DISTANCE ne doivent jamais être supérieures à USE_RADIUS.

Valide

USE_RADIUS=20.0
ATTACHED_DISTANCE=15.0
REZZED_DISTANCE=10.0

Invalide

USE_RADIUS=10.0
ATTACHED_DISTANCE=15.0
06

Animations

Quatre animations indépendantes et facultatives, configurées avec leur nom exact dans l’inventaire.

Chaque animation peut être désactivée

Laissez la valeur d’une animation vide pour qu’elle ne soit pas jouée. Les animations actives et désactivées peuvent être combinées librement.

CARRY_ANIMATION=
SERVE_ANIMATION=
ATTACHED_RECEIVE_ANIMATION=
REZZED_PICKUP_ANIMATION=

CARRY_ANIMATION

Pose permanente de l’avatar qui porte le Dador attaché. Si elle est utilisée, elle doit être préparée en loop. Vide signifie qu’aucune pose de portage n’est jouée.

CARRY_ANIMATION=Anim_Carry

SERVE_ANIMATION

Animation temporaire du porteur lorsqu’il sert. Elle est utilisée uniquement avec le Dador attaché et SIMULTANEOUS_MENUS=NO. Vide signifie que le porteur ne joue aucune animation de service.

SERVE_ANIMATION=Anim_Serve
SERVE_ANIMATION_DURATION=5.0

ATTACHED_RECEIVE_ANIMATION

Animation du destinataire lorsque le Dador est attaché. Elle peut rester vide.

ATTACHED_RECEIVE_ANIMATION=Anim_Receive_Attached
ATTACHED_RECEIVE_ANIMATION_DURATION=5.0

REZZED_PICKUP_ANIMATION

Animation du destinataire lorsque le Dador est rezzé. Elle peut rester vide.

REZZED_PICKUP_ANIMATION=Anim_Pickup_Rezzed
REZZED_PICKUP_ANIMATION_DURATION=5.0

Les trois durées d’animation temporaires acceptent toujours 0.1 .. 60.0 secondes. Si l’animation correspondante est vide, sa durée est simplement ignorée. CARRY_ANIMATION n’a pas de durée.

Utiliser des animations achetées

Il n’est pas nécessaire de les renommer. Si une ligne ANIM_* contient un nom, placez cette animation dans le Dador et indiquez son nom exact dans l’inventaire. Si la ligne est vide, aucune animation n’est requise pour ce rôle.

ATTACHED_RECEIVE_ANIMATION=[Tienda] Take Drink Bento 03

Quand un objet temporaire apparaît

ATTACHED_TEMP_SHOW_DELAY=1.3
REZZED_TEMP_SHOW_DELAY=1.6

Avec une animation de réception active, le délai doit rester dans la durée de cette animation. Si l’animation de réception correspondante est vide, il n’y a aucune animation avec laquelle se synchroniser : l’objet temporaire apparaît immédiatement et ce délai n’intervient pas.

07

Messages de livraison

Utilisez une phrase personnalisée, le message automatique ou les deux.

DELIVERY_MESSAGE

Définit une phrase personnalisée. Le nom du paramètre doit rester DELIVERY_MESSAGE.

DELIVERY_MESSAGE=Que aproveche!

Laissez vide si vous ne voulez pas de phrase personnalisée :

DELIVERY_MESSAGE=

AUTOMATIC_MESSAGE

Utilisez YES pour activer le message automatique et NO pour le désactiver. Ne traduisez pas YES/NO dans Dador Config.

AUTOMATIC_MESSAGE=YES

Avec YES, le Dador ajoute ce format :

<Dador name> has given you <Product name>.
DELIVERY_MESSAGEAutomatiqueRésultat
VideNOAucun message
VideYESAutomatique uniquement
Avec texteNOPersonnalisé uniquement
Avec texteYESPersonnalisé + automatique

MESSAGE_DISTANCE

10Chuchotement · ~10 m
20Chat normal · ~20 m
100Cri · ~100 m
Pourquoi le nom du Dador peut apparaître deux fois

Second Life affiche automatiquement le nom de l’objet qui parle. Le message automatique peut également contenir ce même nom.

08

Créer et ajouter des produits

Comment préparer de zéro un objet ou une notecard compatible avec le Dador.

Ce qu’il vous faut

Pour une copie normale, il suffit de préparer le produit et sa description. Si le produit utilise une partie temporaire, utilisez le Temporary_Script fourni avec le système et, lorsque nécessaire, une notecard nommée exactement Temporary Config. Le manuel explique la configuration ; il n’est pas nécessaire de modifier le code du script.

1. Décider ce que le produit doit remettre

Le Dador lit la description de l’élément principal et utilise deux indicateurs : T pour la partie temporaire et C pour la copie permanente.

DescriptionRésultatUtilisation typique
TEMP=NO;COPY=YESCopie permanente uniquementObjet ou notecard remis dans l’inventaire
TEMP=YES;COPY=NOTemporaire uniquementProp attaché temporairement sans laisser de copie
TEMP=YES;COPY=YESTemporaire + copie permanenteScène temporaire plus copie dans l’inventaire

Une description vide équivaut à TEMP=NO;COPY=YES. N’utilisez pas TEMP=NO;COPY=NO : le Dador le considère comme invalide car il n’y aurait rien à remettre.

2. Choisir la structure du produit

Objet avec copie

Bière
Description: TEMP=NO;COPY=YES

Ne nécessite pas Temporary_Script.

Objet temporaire

Bière
Description: TEMP=YES;COPY=NO

Si TEMP_Bière n’existe pas, l’objet principal peut lui-même servir d’objet temporaire.

Objet + TEMP_

Bière
TEMP_Bière

Si TEMP_Bière existe, le Dador le préfère comme composant temporaire. Le produit visible dans le menu reste Bière.

Notecard + TEMP_

Recette de bière
TEMP_Recette de bière

Pour une notecard avec T=YES, l’objet TEMP_<nom exact> est obligatoire.

3. Préparer l’objet temporaire

L’objet qui fonctionnera comme composant temporaire doit contenir le noyau temporaire et, si nécessaire, sa configuration et ses animations :

Temporary_Script
Temporary Config
Animations propres (facultatives)
Noms exacts

La notecard doit s’appeler exactement Temporary Config. Le préfixe TEMP_ doit également être conservé exactement et suivi du nom complet du produit principal.

La politique TEMP/COPY doit être placée dans la description du produit principal. Si vous utilisez un objet auxiliaire TEMP_, il n’est pas nécessaire de répéter cette politique dans sa description : le Dador utilise celle du produit principal.

4. Configurer Temporary Config

Les paramètres généraux doivent apparaître avant de commencer la séquence ANIMATIONn/DURATIONn.

Si l’objet temporaire ne possède pas d’animations propres, utilise le comportement final par défaut DETACH_AT_END=YES et n’a pas besoin de phrase propre, Temporary Config peut être omise. Pour rester attaché avec DETACH_AT_END=NO, émettre PICKUP_MESSAGE ou contrôler une séquence, Temporary Config est nécessaire.

Temporary Config accepte jusqu’à 100 lignes physiques. Utilisez un point décimal pour les durées, par exemple 4.2.

Sans animations propres

PICKUP_MESSAGE=
MESSAGE_DISTANCE=20
DETACH_AT_END=YES

ANIMATION1=
DURATION1=

Avec une animation

PICKUP_MESSAGE=Vous avez pris une bière.
MESSAGE_DISTANCE=20
DETACH_AT_END=NO

ANIMATION1=ARM PICKUP
DURATION1=4.2

PICKUP_MESSAGE

Texte prononcé par l’objet temporaire environ une seconde après l’attach. Peut rester vide pour ne rien dire.

MESSAGE_DISTANCE

Accepte uniquement 10, 20 ou 100. Si omis, la valeur par défaut est 20.

DETACH_AT_END

YES masque et détache l’objet temporaire à la fin. NO le laisse visible et attaché jusqu’à ce que l’avatar le retire.

ANIMATIONn / DURATIONn

Jusqu’à 10 animations, numérotées consécutivement à partir de 1. Chaque durée réelle doit être comprise entre 0.1 et 60.0 secondes.

La même clé est utilisée dans deux notecards différentes

MESSAGE_DISTANCE est valide dans Temporary Config comme dans Dador Config. Chaque notecard contrôle indépendamment sa propre distance de message.

5. Règles des animations temporaires

  • Les paires doivent être consécutives : ANIMATION1 + DURATION1, puis ANIMATION2 + DURATION2, etc.
  • N’insérez pas PICKUP_MESSAGE, MESSAGE_DISTANCE ou DETACH_AT_END entre une animation et son temps.
  • Le nom doit correspondre exactement à une animation présente dans l’objet temporaire.
  • Une paire vide telle que ANIMATION1= + DURATION1= ferme explicitement la séquence et permet de ne jouer aucune animation même si des animations inutilisées restent dans l’inventaire.
  • Ne déclarez pas de nouvelles animations après une paire vide.

6. Vérifier les permissions

Le Dador vérifie les permissions nécessaires pour remettre des copies et créer des temporaires. Les éléments utilisés comme temporaires doivent autoriser Copy + Transfer, y compris le contenu qui doit les accompagner. Si vous modifiez les permissions après la préparation, répétez le test complet.

7. Tester le produit avant de le placer dans le Dador

Avec Temporary_Script v2.6.4, rezzez manuellement l’objet temporaire. Comme il ne reçoit pas les données de démarrage du Dador, il passe en mode préparation : il ne s’attache pas, ne demande pas de permissions, ne lance pas d’animations et ne se supprime pas.

Le diagnostic vérifie la description TEMP/COPY, Temporary Config, ses paramètres, les animations et l’état général du produit. Quand tout est correct, vous devez obtenir quelque chose comme :

OK: TEMP=YES;COPY=YES (temporary + copy).
PREP v2.6.4 | objeto='Pepo' | anim=1 | secuencia=1
RESULT: READY to be placed in the Dador.
MEM: usada=... libre=...

Si RESULT: NOT READY apparaît, corrigez d’abord les erreurs indiquées. Le diagnostic se relance lorsque l’inventaire change et surveille également le nom et la description pendant la préparation.

8. Placer le produit dans le Dador

  1. Lorsque le diagnostic indique RESULT: READY, reprenez l’objet s’il était rezzé.
  2. Modifiez le Dador et ouvrez Contenu.
  3. Ajoutez le produit principal.
  4. S’il utilise un composant séparé TEMP_, ajoutez-le également.
  5. Conservez sans modification les noms, la description, les scripts, notecards, animations et permissions déjà testés.
  6. Attendez quelques secondes pendant le rechargement du catalogue.
  7. Touchez le Dador et vérifiez que le produit principal apparaît dans le menu.
  8. Effectuez une livraison réelle et vérifiez la partie temporaire ainsi que la copie permanente, selon le cas.
30produits maximum
128éléments d’inventaire maximum
Résumé rapide

Choisissez d’abord TEMP/COPY. Préparez ensuite la partie temporaire si elle existe, configurez Temporary Config, rezzez l’objet et attendez RESULT: READY. Placez seulement ensuite le produit et son éventuel composant TEMP_ dans le Dador et testez une livraison complète.

09

Objets temporaires et TEMP_

Produits visuels pouvant apparaître attachés pendant une livraison.

Certains produits préparés incluent un objet associé dont le nom commence exactement par TEMP_.

Nota de demostración
TEMP_Nota de demostración

Le produit principal apparaît dans le menu. L’élément TEMP_ est interne et n’apparaît pas comme produit séparé.

Ce qu’un temporaire peut faire

  • Disparaître automatiquement après ses animations.
  • Exécuter une ou plusieurs animations propres.
  • Rester attaché après la fin de la séquence.
  • Rester attaché jusqu’à ce que l’avatar le retire manuellement.

Démo de bière

Ajoutez la bière préparée au Dador, ne changez ni son nom ni sa description, attendez le rechargement et sélectionnez-la dans le menu.

Notecard + TEMP_

Ajoutez la notecard et son objet TEMP_ associé sans changer leurs noms. La notecard doit apparaître dans le menu, pas le composant TEMP_.

10

Utilisation rezzée et attachée

Deux façons d’utiliser le même système.

Rezzé
  1. Placez le Dador dans le monde.
  2. L’utilisateur doit se trouver dans USE_RADIUS.
  3. Touchez le Dador et sélectionnez un produit.
  4. Pour terminer la livraison, restez dans REZZED_DISTANCE.
  5. Le destinataire utilise REZZED_PICKUP_ANIMATION.

CARRY_ANIMATION et SERVE_ANIMATION n’interviennent pas en mode rezzé.

Attaché
  1. Attachez le Dador à l’avatar qui servira les produits.
  2. CARRY_ANIMATION démarre automatiquement.
  3. Un autre avatar touche le Dador et choisit un produit.
  4. Le destinataire doit se trouver dans ATTACHED_DISTANCE.
  5. Le destinataire utilise ATTACHED_RECEIVE_ANIMATION.

Avec SIMULTANEOUS_MENUS=NO, le porteur joue également SERVE_ANIMATION.

Le porteur ne peut pas se servir lui-même

L’avatar qui porte le Dador ne peut pas utiliser son propre Dador pendant qu’il le porte. Il est destiné à servir d’autres avatars.

11

Dépannage

Vérifications qui résolvent la plupart des problèmes courants.

Le menu n’apparaît pas

Vérifiez USE_RADIUS, le mode ACCESS, que le Dador a fini de charger, que des produits valides existent et que Dador Config ne contient pas d’erreurs.

J’obtiens « Pas d’accès »

Pour GROUP, vérifiez le groupe du Dador et le groupe actif de l’avatar. Pour LIST, utilisez des Usernames valides, pas des Display Names.

Le Dador indique qu’il est occupé

Avec SIMULTANEOUS_MENUS=NO, c’est normal : une seule personne peut l’utiliser à la fois.

Trop de menus ou de demandes

Le mode simultané accepte jusqu’à 20 sessions de menu actives et 20 sélections en attente.

Le Dador me demande de me rapprocher

Vous pouvez être dans USE_RADIUS tout en étant hors de la distance finale. Vérifiez ATTACHED_DISTANCE ou REZZED_DISTANCE.

Une animation ne fonctionne pas

Vérifiez qu’elle se trouve dans le Dador, que son nom correspond exactement et que la durée est correcte. CARRY_ANIMATION doit aussi être préparée pour loop.

SERVE_ANIMATION ne fonctionne pas

Si SIMULTANEOUS_MENUS=YES, c’est volontaire.

Un temporaire apparaît trop tôt ou trop tard

Ajustez ATTACHED_TEMP_SHOW_DELAY ou REZZED_TEMP_SHOW_DELAY.

Un temporaire ne disparaît pas

Cela peut être correct. Certains produits sont conçus pour rester attachés jusqu’à ce que le destinataire les retire.

Aucun message de livraison n’apparaît

Avec DELIVERY_MESSAGE= et AUTOMATIC_MESSAGE=NO, l’absence de message est le résultat attendu.

MESSAGE_DISTANCE provoque une erreur

Seules les valeurs 10, 20 ou 100 sont acceptées.
