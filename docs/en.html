Dador de objetos

A system for offering products through a menu, either rezzed in-world or attached to an avatar.

What it can do

  • Deliver products to inventory
  • Show attached temporary objects
  • Combine a temporary object + permanent copy
  • Work with several users
  • Use configurable animations
  • Send delivery messages

01

Getting started

Check the contents and prepare the Dador for use.

Dador contents

These four scripts must remain inside the Dador:

Dador_Main v1.4.1
Dador_Config_Productos v1.3.4
Dador_Anim_portador v1.3.1
Dador_Menu_Multiusuario v1.0.1

You will also find Config Dador, Lista Autorizados, the animations used by the Dador, installed products and possible TEMP_ components.

Exact names are required

The main notecard must be named exactly Config Dador. If you use ACCESO=LISTA, the access notecard must be named exactly Lista Autorizados. Do not rename scripts or TEMP_ components.

First launch

  1. Rez a copy of the Dador in an area where you can edit objects and run scripts.
  2. Right-click the Dador and choose Edit.
  3. Open the Contents tab.
  4. Check that all four main scripts are present.
  5. Check that Config Dador is present.
  6. Check that the animations named in Config Dador are actually inside the Dador.
  7. Open Config Dador, change only the documented options and save it.
  8. Wait a few seconds before testing.

The system automatically reloads when its inventory changes, including after saving Config Dador or adding/removing animations, products or TEMP_ components.

02

Config Dador

The control center of the product, without editing the scripts.

Configuration lines use the format NOMBRE=VALOR. The parameter names shown in code examples must not be translated.

NOMBRE=VALOR

Rules

  • Use a dot for decimals: 1.2.
  • Do not use a comma as decimal separator: 1,2.
  • Lines beginning with # are comments.
  • Blank lines are allowed.
  • Config Dador supports up to 100 physical lines.
Minimal example
ACCESO=TODOS
MENUS_SIMULTANEOS=NO

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

Complete example

ACCESO=TODOS

MENUS_SIMULTANEOS=NO

FRASE_DAR=
MENSAJE_AUTOMATICO=SI
DISTANCIA_MENSAJES=20

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

ANIM_PORTAR=Anim_Portar
ANIM_SERVIR=Anim_Servir
ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado

DURACION_ANIM_SERVIR=5.0
DURACION_ANIM_RECIBIR_ANEXADO=5.0
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

RETARDO_APARICION_TEMP_NO_ANEXADO=0
03

Who can use it

Four access modes.

TODOS

ACCESO=TODOS

Any avatar can use the Dador.

PROPIETARIO

ACCESO=PROPIETARIO

Only the owner can use it.

GRUPO

ACCESO=GRUPO

Only avatars with the same active group as the Dador can use it.

LISTA

ACCESO=LISTA

Only avatars included in Lista Autorizados can use it.

Lista Autorizados

Write one Second Life Username per line. Do not use Display Names.

avatar.ejemplo
OtroUsuario

Blank lines and comments beginning with # are allowed. Maximum: 20 avatars. If a Username cannot be resolved, LISTA mode is blocked until it is corrected.

04

Single or simultaneous menus

Choose how the Dador behaves when several people use it.

Classic

MENUS_SIMULTANEOS=NO

Only one person can use the Dador at a time. While that person browses, selects and receives a product, another user will be told that it is busy.

When attached, ANIM_SERVIR works normally in this mode.

Multi-user

MENUS_SIMULTANEOS=SI

Several avatars can open and browse their own menus at the same time. Deliveries are then processed one at a time and in order.

Limits: up to 20 simultaneous menus and 20 pending delivery requests.

Animations in simultaneous mode

When the Dador is attached, ANIM_SERVIR is not played. ANIM_PORTAR, receiver animations, temporary objects and permanent copies continue to work.

Product menu

  • Shows up to 3 products per page.
  • Uses Anterior and Siguiente when more pages are available.
  • Includes Cancelar.
  • Each menu expires after approximately 30 seconds of inactivity.
05

Distances

Three separate values control opening the menu and completing a delivery.

RADIO_USO

0.5 .. 300.0 m

Maximum distance from which an avatar may begin using the Dador and open the menu.

DISTANCIA_ANEXADO

0.1 .. 100.0 m

Final delivery distance while the Dador is attached. It is measured horizontally between the receiver and the avatar carrying the Dador.

DISTANCIA_NO_ANEXADO

0.1 .. 100.0 m

Final delivery distance while the Dador is rezzed. It is measured from the edge of the object.

Mandatory rule

DISTANCIA_ANEXADO and DISTANCIA_NO_ANEXADO must never be greater than RADIO_USO.

Valid

RADIO_USO=20.0
DISTANCIA_ANEXADO=15.0
DISTANCIA_NO_ANEXADO=10.0

Invalid

RADIO_USO=10.0
DISTANCIA_ANEXADO=15.0
06

Animations

Four independent and optional animations, configured using their exact inventory names.

Any animation can be disabled

Leave an animation value empty to prevent it from playing. Enabled and disabled animations can be mixed freely.

ANIM_PORTAR=
ANIM_SERVIR=
ANIM_RECIBIR_ANEXADO=
ANIM_RECOGER_NO_ANEXADO=

ANIM_PORTAR

Permanent pose for the avatar carrying the attached Dador. If used, it should be prepared to loop. Empty means no carrying pose is played.

ANIM_PORTAR=Anim_Portar

ANIM_SERVIR

Temporary serving animation for the carrier. It is used only while attached and only with MENUS_SIMULTANEOS=NO. Empty means the carrier does not play a serving animation.

ANIM_SERVIR=Anim_Servir
DURACION_ANIM_SERVIR=5.0

ANIM_RECIBIR_ANEXADO

Receiver animation when the Dador is attached. It may be left empty.

ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
DURACION_ANIM_RECIBIR_ANEXADO=5.0

ANIM_RECOGER_NO_ANEXADO

Receiver animation when the Dador is rezzed. It may be left empty.

ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

The three temporary animation durations still accept 0.1 .. 60.0 seconds. If the corresponding animation is empty, its duration is simply ignored. ANIM_PORTAR has no duration setting.

Using purchased animations

You do not need to rename them. If an ANIM_* line contains a name, place that animation inside the Dador and enter its exact inventory name. If the line is empty, no animation is required for that role.

ANIM_RECIBIR_ANEXADO=[Tienda] Take Drink Bento 03

When a temporary object appears

RETARDO_APARICION_TEMP_ANEXADO=1.3
RETARDO_APARICION_TEMP_NO_ANEXADO=1.6

With an active receiver animation, the delay must stay within that animation's duration. If the corresponding receiver animation is empty, there is no animation to synchronize with: the temporary object appears immediately and that delay does not take part.

07

Delivery messages

Use a custom sentence, the automatic message, or both.

FRASE_DAR

Sets a custom phrase. The parameter name must remain FRASE_DAR.

FRASE_DAR=Que aproveche!

Leave it empty if you do not want a custom phrase:

FRASE_DAR=

MENSAJE_AUTOMATICO

Use SI to enable the automatic delivery text or NO to disable it. Do not translate SI/NO in Config Dador.

MENSAJE_AUTOMATICO=SI

With SI, the Dador adds the following pattern:

<Nombre del Dador> te ha dado <Nombre del producto>.

08

Create and add products

How to prepare a new object or notecard so it is compatible with the Dador.

What you need

For a normal copy, prepare the product and its description. If the product uses a temporary component, use the Script_Temporal supplied with the system and, when required, a notecard named exactly Config Temporal. This manual explains the configuration; you do not need to edit the script code.

1. Decide what the product must deliver

The Dador reads the description of the main item and uses two flags: T for the temporary part and C for the permanent copy.

DescriptionResultTypical use
T=NO;C=SIPermanent copy onlyObject or notecard delivered to inventory
T=SI;C=NOTemporary onlyProp that appears attached and leaves no copy
T=SI;C=SITemporary + permanent copyTemporary scene plus an inventory copy

An empty description is equivalent to T=NO;C=SI. Do not use T=NO;C=NO: the Dador treats it as invalid because there would be nothing to deliver.

2. Choose the product structure

Object with copy

Beer
Description: T=NO;C=SI

It does not need Script_Temporal.

Temporary object

Beer
Description: T=SI;C=NO

If TEMP_Beer does not exist, the main object itself can act as the temporary object.

Object + TEMP_

Beer
TEMP_Beer

If TEMP_Beer exists, the Dador prefers it as the temporary component. The product shown in the menu remains Beer.

Notecard + TEMP_

Beer recipe
TEMP_Beer recipe

For a notecard with T=SI, the object TEMP_<exact name> is mandatory.

3. Prepare the temporary object

The object that will work as the temporary component must contain the temporary core and, when needed, its configuration and animations:

Script_Temporal
Config Temporal
Own animations (optional)
Exact names

The notecard must be named exactly Config Temporal. The TEMP_ prefix must also be preserved exactly and followed by the complete name of the main product.

4. Configure Config Temporal

General parameters must appear before the ANIMACIONn/TIEMPOn sequence begins.

If the temporary object has no own animations, uses the default final behavior DESANEXAR_AL_FINAL=SI and needs no pickup phrase, Config Temporal may be omitted. If it must remain attached with DESANEXAR_AL_FINAL=NO, emit FRASE_COGER or control a sequence, then Config Temporal is required.

Config Temporal supports up to 100 physical lines. Use a decimal point for times, for example 4.2.

Without own animations

FRASE_COGER=
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=SI

ANIMACION1=
TIEMPO1=

With one animation

FRASE_COGER=You picked up a beer.
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=NO

ANIMACION1=BRAZO COGER
TIEMPO1=4.2

FRASE_COGER

Text spoken by the temporary object about one second after attachment. It can be empty to say nothing.

DISTANCIA_MENSAJE

Only 10, 20 or 100 are accepted. If omitted, it defaults to 20.

DESANEXAR_AL_FINAL

SI hides and detaches the temporary object when it finishes. NO leaves it visible and attached until the avatar removes it.

ANIMACIONn / TIEMPOn

Up to 10 animations, numbered consecutively from 1. Each real duration must be between 0.1 and 60.0 seconds.

Do not confuse the two message-distance parameters

DISTANCIA_MENSAJE belongs to Config Temporal. DISTANCIA_MENSAJES, with a final S, belongs to Config Dador. They are different parameters.

5. Temporary animation rules

  • Pairs must be consecutive: ANIMACION1 + TIEMPO1, then ANIMACION2 + TIEMPO2, and so on.
  • Do not place FRASE_COGER, DISTANCIA_MENSAJE or DESANEXAR_AL_FINAL between an animation and its time.
  • The name must exactly match an animation stored inside the temporary object.
  • An empty pair such as ANIMACION1= + TIEMPO1= explicitly closes the sequence and lets the product run no animations even if unused animations remain in inventory.
  • Do not declare new animations after an empty pair.

6. Check permissions

The Dador validates the permissions required to deliver copies and create temporary objects. Items used as temporaries must allow Copy + Transfer, including the content that must travel with them. If you change permissions after preparing the product, repeat the full test.

7. Test the product before placing it in the Dador

With Script_Temporal v2.6.4, rez the temporary object manually. Because it receives no Dador startup data, it enters preparation mode: it does not attach, request permissions, run animations or delete itself.

The diagnostic checks the T/C description, Config Temporal, its parameters, animations and the general product state. When everything is correct you should see something like:

OK: T=SI;C=SI (temporal + copia).
PREP v2.6.4 | objeto='Pepo' | anim=1 | secuencia=1
RESULTADO: LISTO para introducir en el Dador.
MEM: usada=... libre=...

If RESULTADO: NO LISTO appears, fix the reported errors first. The diagnostic runs again when inventory changes and also watches the name and description while the object is in preparation mode.

8. Put the product into the Dador

  1. When the diagnostic shows LISTO, take the object back if it was rezzed.
  2. Edit the Dador and open Contents.
  3. Add the main product.
  4. If it uses a separate TEMP_ component, add that as well.
  5. Keep the tested names, description, scripts, notecards, animations and permissions unchanged.
  6. Wait a few seconds while the catalog reloads.
  7. Touch the Dador and confirm that the main product appears in the menu.
  8. Perform a real delivery and verify the temporary part and the permanent copy, as applicable.

Quick summary

Choose T/C first. Then prepare the temporary part if there is one, configure Config Temporal, rez it and wait for RESULTADO: LISTO. Only then place the product and any TEMP_ component in the Dador and test a complete delivery.

09

Temporary objects and TEMP_

Visual products that can appear attached during delivery.

Some prepared products include an associated object whose name begins exactly with TEMP_.

Nota de demostración
TEMP_Nota de demostración

The main product appears in the menu. The TEMP_ element is internal and does not appear as a separate product.

What a temporary object may do

  • Disappear automatically after its animations.
  • Run one or more of its own animations.
  • Remain attached after the sequence ends.
  • Remain attached until the avatar removes it manually.

Beer demo

Add the prepared beer to the Dador, do not rename it or alter its description, wait for the reload and select it from the menu.

Notecard + TEMP_

Add both the notecard and its associated TEMP_ object without changing their names. The notecard should appear in the menu, not the TEMP_ component.

10

Rezzed and attached use

Two ways to use the same system.

Rezzed
  1. Place the Dador in-world.
  2. The user must be within RADIO_USO.
  3. Touch the Dador and select a product.
  4. To complete delivery, remain within DISTANCIA_NO_ANEXADO.
  5. The receiver uses ANIM_RECOGER_NO_ANEXADO.

ANIM_PORTAR and ANIM_SERVIR do not take part in rezzed mode.

Attached
  1. Attach the Dador to the avatar who will serve products.
  2. ANIM_PORTAR starts automatically.
  3. Another avatar touches the Dador and chooses a product.
  4. The receiver must be within DISTANCIA_ANEXADO.
  5. The receiver uses ANIM_RECIBIR_ANEXADO.

With MENUS_SIMULTANEOS=NO, the carrier also plays ANIM_SERVIR.

The carrier cannot serve themselves

The avatar wearing the Dador cannot use their own Dador while wearing it. It is intended to serve other avatars.

11

Troubleshooting

Checks that solve most common issues.

The menu does not appear

Check RADIO_USO, the ACCESO mode, that the Dador has finished loading, that valid products exist and that Config Dador contains no errors.

I get “No access”

For GRUPO, check the Dador group and the avatar's active group. For LISTA, use valid Usernames rather than Display Names.

The Dador says it is busy

With MENUS_SIMULTANEOS=NO this is expected: only one person can use it at a time.

Too many menus or requests

Simultaneous mode allows up to 20 active menu sessions and 20 pending selections.

The Dador asks me to move closer

You can be inside RADIO_USO and still be outside the final delivery distance. Check DISTANCIA_ANEXADO or DISTANCIA_NO_ANEXADO.

An animation does not play

Check that the animation is in the Dador, that its name matches exactly and that the configured duration is correct. ANIM_PORTAR must also be prepared to loop.

ANIM_SERVIR does not play

If MENUS_SIMULTANEOS=SI, this is deliberate.

A temporary object appears too early or too late

Adjust RETARDO_APARICION_TEMP_ANEXADO or RETARDO_APARICION_TEMP_NO_ANEXADO.

A temporary object does not disappear

That can be correct. Some products are designed to remain attached until the receiver removes them manually.

No delivery message appears

With FRASE_DAR= and MENSAJE_AUTOMATICO=NO, silence is the correct result.

DISTANCIA_MENSAJES gives an error

It only accepts 10, 20 or 100.
