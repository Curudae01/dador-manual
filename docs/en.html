Delivery

A system for offering products through a menu, either rezzed in-world or attached to an avatar.

Get startedQuick reference
Configurable menusRezzed or attachedObjects and notecardsCompatible temporary objects

What it can do

  • Deliver products to inventory
  • Show attached temporary objects
  • Combine a temporary object + permanent copy
  • Work with several users
  • Use configurable animations
  • Send delivery messages

01

Getting started

Check the contents and prepare the Dador for use.

Dador contents

These four scripts must remain inside the Dador:

Dador_Main v1.4.1
Dador_Config_Products v1.3.4
Dador_Carrier_Animation v1.3.1
Dador_Multiuser_Menu v1.0.1

You will also find Dador Config, Authorized Users, the animations used by the Dador, installed products and possible TEMP_ components.

Exact names are required

The main notecard must be named exactly Dador Config. If you use ACCESS=LIST, the access notecard must be named exactly Authorized Users. Do not rename scripts or TEMP_ components.

First launch

  1. Rez a copy of the Dador in an area where you can edit objects and run scripts.
  2. Right-click the Dador and choose Edit.
  3. Open the Contents tab.
  4. Check that all four main scripts are present.
  5. Check that Dador Config is present.
  6. Check that the animations named in Dador Config are actually inside the Dador.
  7. Open Dador Config, change only the documented options and save it.
  8. Wait a few seconds before testing.

The system automatically reloads when its inventory changes, including after saving Dador Config or adding/removing animations, products or TEMP_ components.

02

Dador Config

The control center of the product, without editing the scripts.

Configuration lines use the format NOMBRE=VALOR. The parameter names shown in code examples must not be translated.

NOMBRE=VALOR

Rules

  • Use a dot for decimals: 1.2.
  • Do not use a comma as decimal separator: 1,2.
  • Lines beginning with # are comments.
  • Blank lines are allowed.
  • Dador Config supports up to 100 physical lines.
Minimal example
ACCESS=ALL
SIMULTANEOUS_MENUS=NO

USE_RADIUS=5.0
ATTACHED_DISTANCE=2.0
REZZED_DISTANCE=1.2

Complete example

ACCESS=ALL

SIMULTANEOUS_MENUS=NO

DELIVERY_MESSAGE=
AUTOMATIC_MESSAGE=YES
MESSAGE_DISTANCE=20

USE_RADIUS=5.0
ATTACHED_DISTANCE=2.0
REZZED_DISTANCE=1.2

CARRY_ANIMATION=Anim_Carry
SERVE_ANIMATION=Anim_Serve
ATTACHED_RECEIVE_ANIMATION=Anim_Receive_Attached
REZZED_PICKUP_ANIMATION=Anim_Pickup_Rezzed

SERVE_ANIMATION_DURATION=5.0
ATTACHED_RECEIVE_ANIMATION_DURATION=5.0
REZZED_PICKUP_ANIMATION_DURATION=5.0

ATTACHED_TEMP_SHOW_DELAY=0
REZZED_TEMP_SHOW_DELAY=0
03

Who can use it

Four access modes.

ALL

ACCESS=ALL

Any avatar can use the Dador.

OWNER

ACCESS=OWNER

Only the owner can use it.

GROUP

ACCESS=GROUP

Only avatars with the same active group as the Dador can use it.

LIST

ACCESS=LIST

Only avatars included in Authorized Users can use it.

Authorized Users

Write one Second Life Username per line. Do not use Display Names.

avatar.ejemplo
OtroUsuario

Blank lines and comments beginning with # are allowed. Maximum: 20 avatars. If a Username cannot be resolved, LIST mode is blocked until it is corrected.

04

Single or simultaneous menus

Choose how the Dador behaves when several people use it.

Classic

SIMULTANEOUS_MENUS=NO

Only one person can use the Dador at a time. While that person browses, selects and receives a product, another user will be told that it is busy.

When attached, SERVE_ANIMATION works normally in this mode.

Multi-user

SIMULTANEOUS_MENUS=YES

Several avatars can open and browse their own menus at the same time. Deliveries are then processed one at a time and in order.

Limits: up to 20 simultaneous menus and 20 pending delivery requests.

Animations in simultaneous mode

When the Dador is attached, SERVE_ANIMATION is not played. CARRY_ANIMATION, receiver animations, temporary objects and permanent copies continue to work.

Product menu

  • Shows up to 3 products per page.
  • Uses Previous and Next when more pages are available.
  • Includes Cancel.
  • Each menu expires after approximately 30 seconds of inactivity.
05

Distances

Three separate values control opening the menu and completing a delivery.

USE_RADIUS

0.5 .. 300.0 m

Maximum distance from which an avatar may begin using the Dador and open the menu.

ATTACHED_DISTANCE

0.1 .. 100.0 m

Final delivery distance while the Dador is attached. It is measured horizontally between the receiver and the avatar carrying the Dador.

REZZED_DISTANCE

0.1 .. 100.0 m

Final delivery distance while the Dador is rezzed. It is measured from the edge of the object.

Mandatory rule

ATTACHED_DISTANCE and REZZED_DISTANCE must never be greater than USE_RADIUS.

Valid

USE_RADIUS=20.0
ATTACHED_DISTANCE=15.0
REZZED_DISTANCE=10.0

Invalid

USE_RADIUS=10.0
ATTACHED_DISTANCE=15.0
06

Animations

Four independent and optional animations, configured using their exact inventory names.

Any animation can be disabled

Leave an animation value empty to prevent it from playing. Enabled and disabled animations can be mixed freely.

CARRY_ANIMATION=
SERVE_ANIMATION=
ATTACHED_RECEIVE_ANIMATION=
REZZED_PICKUP_ANIMATION=

CARRY_ANIMATION

Permanent pose for the avatar carrying the attached Dador. If used, it should be prepared to loop. Empty means no carrying pose is played.

CARRY_ANIMATION=Anim_Carry

SERVE_ANIMATION

Temporary serving animation for the carrier. It is used only while attached and only with SIMULTANEOUS_MENUS=NO. Empty means the carrier does not play a serving animation.

SERVE_ANIMATION=Anim_Serve
SERVE_ANIMATION_DURATION=5.0

ATTACHED_RECEIVE_ANIMATION

Receiver animation when the Dador is attached. It may be left empty.

ATTACHED_RECEIVE_ANIMATION=Anim_Receive_Attached
ATTACHED_RECEIVE_ANIMATION_DURATION=5.0

REZZED_PICKUP_ANIMATION

Receiver animation when the Dador is rezzed. It may be left empty.

REZZED_PICKUP_ANIMATION=Anim_Pickup_Rezzed
REZZED_PICKUP_ANIMATION_DURATION=5.0

The three temporary animation durations still accept 0.1 .. 60.0 seconds. If the corresponding animation is empty, its duration is simply ignored. CARRY_ANIMATION has no duration setting.

Using purchased animations

You do not need to rename them. If an ANIM_* line contains a name, place that animation inside the Dador and enter its exact inventory name. If the line is empty, no animation is required for that role.

ATTACHED_RECEIVE_ANIMATION=[Tienda] Take Drink Bento 03

When a temporary object appears

ATTACHED_TEMP_SHOW_DELAY=1.3
REZZED_TEMP_SHOW_DELAY=1.6

With an active receiver animation, the delay must stay within that animation's duration. If the corresponding receiver animation is empty, there is no animation to synchronize with: the temporary object appears immediately and that delay does not take part.

07

Delivery messages

Use a custom sentence, the automatic message, or both.

DELIVERY_MESSAGE

Sets a custom phrase. The parameter name must remain DELIVERY_MESSAGE.

DELIVERY_MESSAGE=Que aproveche!

Leave it empty if you do not want a custom phrase:

DELIVERY_MESSAGE=

AUTOMATIC_MESSAGE

Use YES to enable the automatic delivery text or NO to disable it. Do not translate YES/NO in Dador Config.

AUTOMATIC_MESSAGE=YES

With YES, the Dador adds the following pattern:

<Dador name> has given you <Product name>.

Why the Dador name may appear twice

Second Life automatically displays the name of the speaking object. The automatic message may also contain that same object name.

08

Create and add products

How to prepare a new object or notecard so it is compatible with the Dador.

What you need

For a normal copy, prepare the product and its description. If the product uses a temporary component, use the Temporary_Script supplied with the system and, when required, a notecard named exactly Temporary Config. This manual explains the configuration; you do not need to edit the script code.

1. Decide what the product must deliver

The Dador reads the description of the main item and uses two flags: T for the temporary part and C for the permanent copy.

DescriptionResultTypical use
TEMP=NO;COPY=YESPermanent copy onlyObject or notecard delivered to inventory
TEMP=YES;COPY=NOTemporary onlyProp that appears attached and leaves no copy
TEMP=YES;COPY=YESTemporary + permanent copyTemporary scene plus an inventory copy

An empty description is equivalent to TEMP=NO;COPY=YES. Do not use TEMP=NO;COPY=NO: the Dador treats it as invalid because there would be nothing to deliver.

2. Choose the product structure

Object with copy

Beer
Description: TEMP=NO;COPY=YES

It does not need Temporary_Script.

Temporary object

Beer
Description: TEMP=YES;COPY=NO

If TEMP_Beer does not exist, the main object itself can act as the temporary object.

Object + TEMP_

Beer
TEMP_Beer

If TEMP_Beer exists, the Dador prefers it as the temporary component. The product shown in the menu remains Beer.

Notecard + TEMP_

Beer recipe
TEMP_Beer recipe

For a notecard with T=YES, the object TEMP_<exact name> is mandatory.

3. Prepare the temporary object

The object that will work as the temporary component must contain the temporary core and, when needed, its configuration and animations:

Temporary_Script
Temporary Config
Own animations (optional)
Exact names

The notecard must be named exactly Temporary Config. The TEMP_ prefix must also be preserved exactly and followed by the complete name of the main product.

The TEMP/COPY policy belongs in the description of the main product. If you use a separate TEMP_ helper object, you do not need to duplicate that policy in the helper description: the Dador uses the main product policy.

4. Configure Temporary Config

General parameters must appear before the ANIMATIONn/DURATIONn sequence begins.

If the temporary object has no own animations, uses the default final behavior DETACH_AT_END=YES and needs no pickup phrase, Temporary Config may be omitted. If it must remain attached with DETACH_AT_END=NO, emit PICKUP_MESSAGE or control a sequence, then Temporary Config is required.

Temporary Config supports up to 100 physical lines. Use a decimal point for times, for example 4.2.

Without own animations

PICKUP_MESSAGE=
MESSAGE_DISTANCE=20
DETACH_AT_END=YES

ANIMATION1=
DURATION1=

With one animation

PICKUP_MESSAGE=You picked up a beer.
MESSAGE_DISTANCE=20
DETACH_AT_END=NO

ANIMATION1=ARM PICKUP
DURATION1=4.2

PICKUP_MESSAGE

Text spoken by the temporary object about one second after attachment. It can be empty to say nothing.

MESSAGE_DISTANCE

Only 10, 20 or 100 are accepted. If omitted, it defaults to 20.

DETACH_AT_END

YES hides and detaches the temporary object when it finishes. NO leaves it visible and attached until the avatar removes it.

ANIMATIONn / DURATIONn

Up to 10 animations, numbered consecutively from 1. Each real duration must be between 0.1 and 60.0 seconds.

The same key is used in two different notecards

MESSAGE_DISTANCE is valid in both Temporary Config and Dador Config. Each notecard controls its own independent message distance.

5. Temporary animation rules

  • Pairs must be consecutive: ANIMATION1 + DURATION1, then ANIMATION2 + DURATION2, and so on.
  • Do not place PICKUP_MESSAGE, MESSAGE_DISTANCE or DETACH_AT_END between an animation and its time.
  • The name must exactly match an animation stored inside the temporary object.
  • An empty pair such as ANIMATION1= + DURATION1= explicitly closes the sequence and lets the product run no animations even if unused animations remain in inventory.
  • Do not declare new animations after an empty pair.

6. Check permissions

The Dador validates the permissions required to deliver copies and create temporary objects. Items used as temporaries must allow Copy + Transfer, including the content that must travel with them. If you change permissions after preparing the product, repeat the full test.

7. Test the product before placing it in the Dador

With Temporary_Script v2.6.4, rez the temporary object manually. Because it receives no Dador startup data, it enters preparation mode: it does not attach, request permissions, run animations or delete itself.

The diagnostic checks the TEMP/COPY description, Temporary Config, its parameters, animations and the general product state. When everything is correct you should see something like:

OK: TEMP=YES;COPY=YES (temporary + copy).
PREP v2.6.4 | objeto='Pepo' | anim=1 | secuencia=1
RESULT: READY to be placed in the Dador.
MEM: usada=... libre=...

If RESULT: NOT READY appears, fix the reported errors first. The diagnostic runs again when inventory changes and also watches the name and description while the object is in preparation mode.

8. Put the product into the Dador

  1. When the diagnostic shows RESULT: READY, take the object back if it was rezzed.
  2. Edit the Dador and open Contents.
  3. Add the main product.
  4. If it uses a separate TEMP_ component, add that as well.
  5. Keep the tested names, description, scripts, notecards, animations and permissions unchanged.
  6. Wait a few seconds while the catalog reloads.
  7. Touch the Dador and confirm that the main product appears in the menu.
  8. Perform a real delivery and verify the temporary part and the permanent copy, as applicable.

Quick summary

Choose TEMP/COPY first. Then prepare the temporary part if there is one, configure Temporary Config, rez it and wait for RESULT: READY. Only then place the product and any TEMP_ component in the Dador and test a complete delivery.

09

Temporary objects and TEMP_

Visual products that can appear attached during delivery.

Some prepared products include an associated object whose name begins exactly with TEMP_.

Nota de demostración
TEMP_Nota de demostración

The main product appears in the menu. The TEMP_ element is internal and does not appear as a separate product.

What a temporary object may do

  • Disappear automatically after its animations.
  • Run one or more of its own animations.
  • Remain attached after the sequence ends.
  • Remain attached until the avatar removes it manually.

Beer demo

Add the prepared beer to the Dador, do not rename it or alter its description, wait for the reload and select it from the menu.

Notecard + TEMP_

Add both the notecard and its associated TEMP_ object without changing their names. The notecard should appear in the menu, not the TEMP_ component.

10

Rezzed and attached use

Two ways to use the same system.

Rezzed
  1. Place the Dador in-world.
  2. The user must be within USE_RADIUS.
  3. Touch the Dador and select a product.
  4. To complete delivery, remain within REZZED_DISTANCE.
  5. The receiver uses REZZED_PICKUP_ANIMATION.

CARRY_ANIMATION and SERVE_ANIMATION do not take part in rezzed mode.

Attached
  1. Attach the Dador to the avatar who will serve products.
  2. CARRY_ANIMATION starts automatically.
  3. Another avatar touches the Dador and chooses a product.
  4. The receiver must be within ATTACHED_DISTANCE.
  5. The receiver uses ATTACHED_RECEIVE_ANIMATION.

With SIMULTANEOUS_MENUS=NO, the carrier also plays SERVE_ANIMATION.

The carrier cannot serve themselves

The avatar wearing the Dador cannot use their own Dador while wearing it. It is intended to serve other avatars.

11

Troubleshooting

Checks that solve most common issues.

The menu does not appear

Check USE_RADIUS, the ACCESS mode, that the Dador has finished loading, that valid products exist and that Dador Config contains no errors.

I get “No access”

For GROUP, check the Dador group and the avatar's active group. For LIST, use valid Usernames rather than Display Names.

The Dador says it is busy

With SIMULTANEOUS_MENUS=NO this is expected: only one person can use it at a time.

Too many menus or requests

Simultaneous mode allows up to 20 active menu sessions and 20 pending selections.

The Dador asks me to move closer

You can be inside USE_RADIUS and still be outside the final delivery distance. Check ATTACHED_DISTANCE or REZZED_DISTANCE.

An animation does not play

Check that the animation is in the Dador, that its name matches exactly and that the configured duration is correct. CARRY_ANIMATION must also be prepared to loop.

SERVE_ANIMATION does not play

If SIMULTANEOUS_MENUS=YES, this is deliberate.

A temporary object appears too early or too late

Adjust ATTACHED_TEMP_SHOW_DELAY or REZZED_TEMP_SHOW_DELAY.

A temporary object does not disappear

That can be correct. Some products are designed to remain attached until the receiver removes them manually.

No delivery message appears

With DELIVERY_MESSAGE= and AUTOMATIC_MESSAGE=NO, silence is the correct result.

MESSAGE_DISTANCE gives an error

It only accepts 10, 20 or 100.
