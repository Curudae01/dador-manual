Delivery

Un sistema para ofrecer productos mediante menú, tanto rezzado en el mundo como anexado a un avatar.

Empezar Referencia rápida
Menús configurables Rezzado o anexado Objetos y notecards Temporales compatibles

Qué puede hacer

  • Entregar productos al inventario
  • Mostrar objetos temporales anexados
  • Combinar temporal + copia permanente
  • Trabajar con varios usuarios
  • Usar animaciones configurables
  • Emitir mensajes de entrega

No hay coincidencias

Prueba con otro término. Hasta los manuales tienen derecho a no entendernos a la primera.

01

Primeros pasos

Comprueba el contenido y deja el Dador listo para trabajar.

Contenido del Dador

Dentro del Dador deben permanecer estos cuatro scripts:

Dador_Main v1.4.1
Dador_Config_Productos v1.3.4
Dador_Anim_portador v1.3.1
Dador_Menu_Multiusuario v1.0.1

También encontrarás Config Dador, Lista Autorizados, las animaciones utilizadas, productos y posibles componentes TEMP_.

Nombres obligatorios

La notecard principal debe llamarse exactamente Config Dador. Si usas ACCESO=LISTA, la notecard debe llamarse exactamente Lista Autorizados.

Primera puesta en marcha

  1. Rezea una copia del Dador en una zona donde puedas editar objetos y ejecutar scripts.
  2. Haz clic derecho sobre el Dador y entra en Editar.
  3. Abre la pestaña Contenido.
  4. Comprueba que están los cuatro scripts principales.
  5. Comprueba que existe Config Dador.
  6. Comprueba que las animaciones indicadas en la configuración están dentro del Dador.
  7. Abre Config Dador, ajusta las opciones necesarias y guarda.
  8. Espera unos segundos antes de probar.

El sistema recarga automáticamente la configuración cuando cambia el inventario: al guardar la notecard, añadir o quitar animaciones, productos o componentes TEMP_.

02

Config Dador

El centro de control del producto, sin necesidad de tocar los scripts.

La configuración utiliza líneas con el formato NOMBRE=VALOR.

Reglas

  • Usa punto para decimales: 1.2.
  • No uses coma decimal: 1,2.
  • Las líneas que empiezan por # son comentarios.
  • Puedes dejar líneas vacías.
  • Admite hasta 100 líneas físicas.
Ejemplo mínimo 
ACCESO=TODOS
MENUS_SIMULTANEOS=NO

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

Ejemplo completo

ACCESO=TODOS

MENUS_SIMULTANEOS=NO

FRASE_DAR=
MENSAJE_AUTOMATICO=SI
DISTANCIA_MENSAJES=20

RADIO_USO=5.0
DISTANCIA_ANEXADO=2.0
DISTANCIA_NO_ANEXADO=1.2

ANIM_PORTAR=Anim_Portar
ANIM_SERVIR=Anim_Servir
ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado

DURACION_ANIM_SERVIR=5.0
DURACION_ANIM_RECIBIR_ANEXADO=5.0
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

RETARDO_APARICION_TEMP_ANEXADO=0
RETARDO_APARICION_TEMP_NO_ANEXADO=0
03

Quién puede usarlo

Cuatro modos de acceso.

TODOS

ACCESO=TODOS

Cualquier avatar puede utilizar el Dador.

PROPIETARIO

ACCESO=PROPIETARIO

Solo puede utilizarlo el propietario.

GRUPO

ACCESO=GRUPO

Requiere que el avatar tenga activo el mismo grupo que el Dador.

LISTA

ACCESO=LISTA

Solo permite los avatares incluidos en Lista Autorizados.

Lista Autorizados

Escribe un Username de Second Life por línea. No uses Display Names.

avatar.ejemplo
OtroUsuario

Admite comentarios con #, líneas vacías y hasta 20 avatares. Si un Username no puede resolverse, el modo LISTA se bloquea hasta corregirlo.

04

Menú individual o simultáneo

Elige cómo se comporta el Dador cuando llegan varias personas.

Clásico

MENUS_SIMULTANEOS=NO

Solo una persona puede utilizar el Dador cada vez. Mientras navega, selecciona y recibe, otra persona verá que está ocupado.

Con el Dador anexado, ANIM_SERVIR funciona normalmente.

Multiusuario

MENUS_SIMULTANEOS=SI

Varios avatares pueden abrir y navegar por sus propios menús. Las entregas se procesan una a una y en orden.

Máximo: 20 menús y 20 solicitudes pendientes.

Animaciones en modo simultáneo

Si el Dador está anexado, ANIM_SERVIR no se reproduce. ANIM_PORTAR, las animaciones del receptor, los temporales y las copias siguen funcionando.

El menú de productos

  • Muestra hasta 3 productos por página.
  • Usa Anterior y Siguiente cuando hay más páginas.
  • Incluye Cancelar.
  • Caduca aproximadamente después de 30 segundos sin actividad.
05

Distancias

Tres parámetros distintos para abrir el menú y completar una entrega.

RADIO_USO

0.5 .. 300.0 m

Distancia máxima desde la que un avatar puede comenzar a utilizar el Dador y abrir el menú.

DISTANCIA_ANEXADO

0.1 .. 100.0 m

Distancia final cuando el Dador está anexado. Se mide horizontalmente entre receptor y portador.

DISTANCIA_NO_ANEXADO

0.1 .. 100.0 m

Distancia final cuando el Dador está rezzado. Se calcula desde el borde del objeto.

Regla obligatoria

DISTANCIA_ANEXADO y DISTANCIA_NO_ANEXADO nunca pueden superar RADIO_USO.

Válido

RADIO_USO=20.0
DISTANCIA_ANEXADO=15.0
DISTANCIA_NO_ANEXADO=10.0

Inválido

RADIO_USO=10.0
DISTANCIA_ANEXADO=15.0
06

Animaciones

Cuatro animaciones independientes y opcionales, configuradas por nombre exacto.

Puedes desactivar cualquiera

Deja vacío el valor de una animación para no reproducirla. Puedes combinar animaciones activas y desactivadas libremente.

ANIM_PORTAR=
ANIM_SERVIR=
ANIM_RECIBIR_ANEXADO=
ANIM_RECOGER_NO_ANEXADO=

ANIM_PORTAR

Pose permanente del avatar que lleva el Dador anexado. Si se usa, debe estar preparada para loop. Vacía significa que no habrá pose de portar.

ANIM_PORTAR=Anim_Portar

ANIM_SERVIR

Animación temporal del portador. Solo se usa con el Dador anexado y MENUS_SIMULTANEOS=NO. Vacía significa que el portador no reproduce animación de servir.

ANIM_SERVIR=Anim_Servir
DURACION_ANIM_SERVIR=5.0

ANIM_RECIBIR_ANEXADO

Animación del receptor cuando el Dador está anexado. Puede quedar vacía.

ANIM_RECIBIR_ANEXADO=Anim_Recibir_anexado
DURACION_ANIM_RECIBIR_ANEXADO=5.0

ANIM_RECOGER_NO_ANEXADO

Animación del receptor cuando el Dador está rezzado. Puede quedar vacía.

ANIM_RECOGER_NO_ANEXADO=Anim_Recoger_no_anexado
DURACION_ANIM_RECOGER_NO_ANEXADO=5.0

Las tres duraciones temporales siguen aceptando 0.1 .. 60.0 segundos. Si su animación está vacía, la duración simplemente se ignora. ANIM_PORTAR no tiene duración.

Usar animaciones compradas

No necesitas renombrarlas. Si una línea ANIM_* contiene un nombre, introduce esa animación en el Dador y escribe su nombre exacto. Si la línea está vacía, no es necesario tener ninguna animación para ese puesto.

ANIM_RECIBIR_ANEXADO=[Tienda] Take Drink Bento 03

Cuándo aparece un objeto temporal

RETARDO_APARICION_TEMP_ANEXADO=1.3
RETARDO_APARICION_TEMP_NO_ANEXADO=1.6

Con una animación de recepción activa, el retardo debe respetar su duración. Si la animación de recepción correspondiente está vacía, no hay animación con la que sincronizar: el temporal se muestra inmediatamente y ese retardo no interviene.

08

Crear y añadir productos

Cómo preparar desde cero un objeto o una notecard compatible con el Dador.

Qué necesitas

Para una copia normal basta con preparar el producto y su descripción. Si el producto usa una parte temporal, utiliza el Script_Temporal suministrado con el sistema y, cuando corresponda, una notecard llamada exactamente Config Temporal. El manual explica la configuración; no necesitas editar el código del script.

1. Decide qué debe entregar el producto

El Dador lee la descripción del elemento principal y usa dos indicadores: T para la parte temporal y C para la copia permanente.

DescripciónResultadoUso típico
T=NO;C=SISolo copia permanenteObjeto o notecard entregado al inventario
T=SI;C=NOSolo temporalProp que aparece anexado y no deja copia
T=SI;C=SITemporal + copia permanenteEscena temporal y además una copia en inventario

Una descripción vacía equivale a T=NO;C=SI. No uses T=NO;C=NO: el Dador lo considera inválido porque no habría nada que entregar.

2. Elige la estructura del producto

Objeto con copia

Cerveza
Descripción: T=NO;C=SI

No necesita Script_Temporal.

Objeto temporal

Cerveza
Descripción: T=SI;C=NO

Si no existe TEMP_Cerveza, el propio objeto puede actuar como temporal.

Objeto + TEMP_

Cerveza
TEMP_Cerveza

Si existe TEMP_Cerveza, el Dador lo prefiere como componente temporal. El producto visible en el menú sigue siendo Cerveza.

Notecard + TEMP_

Receta de cerveza
TEMP_Receta de cerveza

Para una notecard con T=SI, el objeto TEMP_<nombre exacto> es obligatorio.

3. Prepara el objeto temporal

El objeto que vaya a funcionar como temporal debe contener el núcleo temporal y, si necesita configuración propia, la notecard y las animaciones correspondientes:

Script_Temporal
Config Temporal
Animaciones propias (opcionales)
Nombres exactos

La notecard debe llamarse exactamente Config Temporal. El prefijo TEMP_ también debe conservarse exactamente y seguido del nombre completo del producto principal.

La política T/C se escribe en la descripción del producto principal. Si usas un objeto auxiliar TEMP_, no necesitas duplicar esa política en la descripción del auxiliar: el Dador usa la del producto principal.

4. Configura Config Temporal

Los parámetros generales deben ir antes de comenzar la secuencia ANIMACIONn/TIEMPOn.

Si el temporal no contiene animaciones propias, usa el comportamiento final por defecto DESANEXAR_AL_FINAL=SI y no necesitas frase propia, Config Temporal puede omitirse. Si quieres que permanezca anexado con DESANEXAR_AL_FINAL=NO, emitir FRASE_COGER o controlar una secuencia, sí necesitas Config Temporal.

Config Temporal admite hasta 100 líneas físicas. Los tiempos usan punto decimal, por ejemplo 4.2.

Sin animaciones propias

FRASE_COGER=
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=SI

ANIMACION1=
TIEMPO1=

Con una animación

FRASE_COGER=Has cogido una cerveza.
DISTANCIA_MENSAJE=20
DESANEXAR_AL_FINAL=NO

ANIMACION1=BRAZO COGER
TIEMPO1=4.2

FRASE_COGER

Texto que dice el propio temporal aproximadamente un segundo después del attach. Puede quedar vacío para no decir nada.

DISTANCIA_MENSAJE

Admite únicamente 10, 20 o 100. Si se omite, usa 20.

DESANEXAR_AL_FINAL

SI hace que el temporal se oculte y se desanexe al terminar. NO lo deja visible y anexado hasta que el avatar lo retire.

ANIMACIONn / TIEMPOn

Hasta 10 animaciones, numeradas consecutivamente desde 1. Cada tiempo real debe estar entre 0.1 y 60.0 segundos.

No confundas las dos distancias de mensajes

DISTANCIA_MENSAJE pertenece a Config Temporal. DISTANCIA_MENSAJES, con S final, pertenece a Config Dador. Son parámetros distintos.

5. Reglas de las animaciones del temporal

  • Los pares deben ser consecutivos: ANIMACION1 + TIEMPO1, después ANIMACION2 + TIEMPO2, etc.
  • No introduzcas FRASE_COGER, DISTANCIA_MENSAJE o DESANEXAR_AL_FINAL entre una animación y su tiempo.
  • El nombre debe coincidir exactamente con una animación existente dentro del objeto temporal.
  • Un par vacío como ANIMACION1= + TIEMPO1= cierra expresamente la secuencia y permite no ejecutar animaciones aunque queden animaciones sin usar en el inventario.
  • Después de un par vacío no declares nuevas animaciones.

6. Comprueba permisos

El Dador valida los permisos necesarios para poder entregar copias y crear temporales. Los elementos utilizados como temporales deben permitir Copy + Transfer, incluido el contenido que deba viajar con ellos. Si cambias permisos después de preparar el producto, repite la prueba completa.

7. Prueba el producto antes de meterlo en el Dador

Con Script_Temporal v2.6.4, rezea manualmente el objeto temporal. Al no recibir los datos de arranque del Dador entra en modo preparación: no se anexa, no solicita permisos, no ejecuta animaciones y no se elimina.

El diagnóstico comprueba la descripción T/C, Config Temporal, sus parámetros, las animaciones y el estado general del producto. Cuando todo está correcto debe aparecer algo como:

OK: T=SI;C=SI (temporal + copia).
PREP v2.6.4 | objeto='Pepo' | anim=1 | secuencia=1
RESULTADO: LISTO para introducir en el Dador.
MEM: usada=... libre=...

Si aparece RESULTADO: NO LISTO, corrige primero los errores indicados. El diagnóstico vuelve a ejecutarse al cambiar el inventario y también vigila nombre y descripción mientras el objeto está en preparación.

8. Introduce el producto en el Dador

  1. Cuando el diagnóstico indique LISTO, recoge el objeto si lo tenías rezzado.
  2. Edita el Dador y abre Contenido.
  3. Introduce el producto principal.
  4. Si utiliza un componente separado TEMP_, introdúcelo también.
  5. Conserva nombres, descripción, scripts, notecards, animaciones y permisos ya probados.
  6. Espera unos segundos mientras se recarga el catálogo.
  7. Toca el Dador y comprueba que el producto principal aparece en el menú.
  8. Realiza una entrega real y verifica tanto la parte temporal como la copia permanente que corresponda.
30productos máximos
128elementos totales de inventario
Resumen rápido

Primero decide T/C. Después prepara el temporal si existe, configura Config Temporal, rezea y espera RESULTADO: LISTO. Solo entonces introduce el producto y su posible TEMP_ en el Dador y prueba una entrega completa.

09

Objetos temporales y TEMP_

Productos visuales que pueden aparecer anexados durante la entrega.

Algunos productos incluyen un objeto asociado cuyo nombre empieza exactamente por TEMP_.

Nota de demostración
TEMP_Nota de demostración

El producto principal aparece en el menú. El elemento TEMP_ es interno y no aparece como producto independiente.

Qué puede hacer un temporal

  • desaparecer automáticamente después de sus animaciones;
  • ejecutar una o varias animaciones propias;
  • permanecer anexado después de terminar;
  • quedarse anexado hasta que el avatar lo retire manualmente.

Cerveza de demostración

Arrástrala al contenido, no la renombres ni modifiques su descripción y selecciónala desde el menú.

Nota + TEMP_

Introduce la nota y su objeto asociado sin cambiar los nombres. En el menú debe aparecer la nota, no el componente TEMP_.

10

Uso rezzado y anexado

Dos formas de trabajar con el mismo sistema.

Rezzado
  1. Coloca el Dador en el mundo.
  2. El usuario debe estar dentro de RADIO_USO.
  3. Toca el Dador y selecciona un producto.
  4. Para completar la entrega debe estar dentro de DISTANCIA_NO_ANEXADO.
  5. El receptor usa ANIM_RECOGER_NO_ANEXADO.

ANIM_PORTAR y ANIM_SERVIR no intervienen.

Anexado
  1. Anexa el Dador al avatar que va a servir.
  2. ANIM_PORTAR comienza automáticamente.
  3. Otro avatar toca y elige un producto.
  4. Debe estar dentro de DISTANCIA_ANEXADO.
  5. El receptor usa ANIM_RECIBIR_ANEXADO.

Con menús clásicos también se reproduce ANIM_SERVIR.

El portador no se sirve a sí mismo

El avatar que lleva el Dador no puede utilizar su propio Dador mientras lo lleva puesto.

11

Problemas frecuentes

Las comprobaciones que resuelven la mayoría de incidencias.

El menú no aparece

Comprueba RADIO_USO, el modo ACCESO, que el Dador haya terminado de cargar, que existan productos válidos y que Config Dador no contenga errores.

“No tienes acceso”

En GRUPO, revisa el grupo del Dador y el grupo activo del avatar. En LISTA, usa Usernames válidos y no Display Names.

El Dador dice que está ocupado

Con MENUS_SIMULTANEOS=NO es normal: solo una persona puede utilizarlo cada vez.

Hay demasiados menús o solicitudes

En modo simultáneo hay un máximo de 20 sesiones y 20 solicitudes pendientes.

El Dador pide que me acerque

Puedes estar dentro de RADIO_USO para abrir el menú pero fuera de la distancia final de entrega. Revisa DISTANCIA_ANEXADO o DISTANCIA_NO_ANEXADO.

Una animación no funciona

Comprueba que existe dentro del Dador, que el nombre coincide exactamente y que la duración es correcta. Para ANIM_PORTAR, asegúrate además de que es una animación preparada para loop.

ANIM_SERVIR no se reproduce

Si MENUS_SIMULTANEOS=SI, está desactivada deliberadamente.

El temporal aparece demasiado pronto o tarde

Ajusta RETARDO_APARICION_TEMP_ANEXADO o RETARDO_APARICION_TEMP_NO_ANEXADO.

El temporal no desaparece

Puede ser correcto: algunos productos están preparados para permanecer anexados hasta que el receptor los quite.

No aparece ningún mensaje

Con FRASE_DAR= y MENSAJE_AUTOMATICO=NO, el silencio es el comportamiento correcto.

DISTANCIA_MENSAJES da error

Solo admite 10, 20 o 100.

Inventario demasiado grande

El inventario total del Dador no debe superar 128 elementos.
